# Shop Team — 협업 규칙

이 폴더는 AgentO 데모 팀이 함께 쓰는 작업 공간이다. 제품은 **쇼핑몰 화면 하나(상품 목록 + 장바구니)** 이고,
내용은 `BRIEF.md` 에 있다. 문서·보고는 한국어로 쓴다.

## 팀과 담당

| AgentO | 세션 | 담당 |
|---|---|---|
| 쇼핑몰 (프로젝트) | Coach · 쇼핑몰 | PM. 하루 계획, 선수에게 직접 지시, 보고 취합, 감독에게 하루 한 번 보고 |
| 쇼핑몰 (프로젝트) | Codex 검토 | 교차 검증. 끝난 조각을 다른 모델로 확인만 한다(파일을 고치지 않는다) |
| 기획 (파트) | 기획자 | 요건정의(`docs/requirements.md`), 화면 설계(`design/wireframe.html`), 질의 응답, Coach 의 지시로 `wbs.md`·`reports/daily/` 갱신 |
| 개발 (파트) | 개발자 1 · 상품목록 / 개발자 2 · 장바구니 | 요건 분석, 구현(`src/`), backlog 버그 수정 |
| 테스트 (파트) | 테스터 | 테스트 케이스(`tc/test-cases.md`), 자동 테스트(`tests/`), 테스트 실행, backlog 등록·검증 |

파트 코치는 없다. 지시는 Coach 에게서 바로 오고, 끝나면 보고도 Coach 에게 바로 간다.

## 파일 규칙 — 자기 영역만 고친다

| 파일 | 쓰는 사람 | 다른 사람은 |
|---|---|---|
| `wbs.md`, `reports/daily/*` | 기획자 (Coach 의 지시로) | 읽기만. 진행 상황은 끝난 일의 답에 적는다 |
| `docs/requirements.md`, `design/*` | 기획자 | 읽기만. 모호하면 기획자에게 질문 (`send_to_session`) |
| `src/*` | 개발자 | 테스터는 고치지 않는다 — 버그는 backlog 에 등록 |
| `tc/*`, `tests/*` | 테스터 | 개발자는 고치지 않는다 — 테스트가 틀렸다고 보면 테스터에게 말한다 |
| `backlog.md` | 테스터가 등록, 개발자가 Fixed 로, 테스터가 Verified/Reopened/Closed 로 | 행을 지우지 않는다 |

## backlog.md 형식

한 버그가 한 행이다. ID 는 `BUG-001` 부터 순서대로.

| 상태 | 뜻 | 누가 바꾸나 |
|---|---|---|
| Open | 새 버그 | 테스터 (등록) |
| Fixed | 수정함 — 비고에 무엇을 고쳤는지 | 개발자 |
| Verified | 수정 확인 | 테스터 |
| Reopened | 다시 실패 | 테스터 |
| Closed | 종료 | 테스터 (Coach 가 일일 정리를 지시할 때) |

## 하루 진행 (매일 반복)

1. Coach 가 `wbs.md` 와 `backlog.md` 를 보고 오늘 할 일을 정해 선수 각자에게 한 메시지로 넘긴다. 메시지 머리의 `#T` 번호가 그 일의 이름표다.
2. 기획자는 요건과 화면을 다듬고, 개발·테스트의 질문에 답한다.
3. 개발자는 WBS 의 다음 작업을 구현하고, **backlog 의 Open/Reopened 버그를 매일 확인해 고친다.**
4. 테스터는 테스트 케이스를 늘리고 `npm test` 와 화면 확인으로 테스트한 뒤, **Fixed 버그를 검증하고 새 버그를 등록한다.**
5. 각자 끝나면 **마지막 답이 곧 보고다** — 첫 줄 `기능: …`, 그 다음 한 일·바뀐 파일·확인 방법·결정이 필요한 것을 몇 줄로. `report_up` 은 막혔거나 결정이 필요할 때만 쓴다.
6. Coach 는 코드가 바뀐 조각을 `Codex 검토` 에 보내 교차 검증하고, 문제는 해당 선수에게 돌려보낸다.
7. 하루 끝에 Coach 의 지시로 기획자가 `wbs.md` 진행률과 `reports/daily/day-N.md` 를 쓰고, Coach 가 감독에게 하루 요약을 한 번 보고한다.

하루 일은 작게 잡는다. 못 끝낸 것은 다음 날로 넘기고 WBS 에 적는다.

## 프로젝트 메모리

모든 세션은 시작할 때 프로젝트 메모리(결정·관례·파일 지도·함정)를 받는다. 다른 세션도 알아야 할 것을 알게 되면
`update_memory` 로 한 줄씩 남기고, 낡은 줄은 교체하거나 지운다. 폴더를 다시 읽지 않아도 일할 수 있게 하는 것이 목적이다.

## 기술 조건

- 빌드 도구 없음: `src/index.html` 을 브라우저로 바로 연다. 순수 HTML/CSS/JS(ES 모듈).
- 계산 로직은 `src/cart.js`, `src/products.js` 처럼 DOM 과 분리해 테스트할 수 있게 한다.
- 자동 테스트: Node 내장 테스트(`node --test`). `npm test` 로 실행한다. 외부 패키지를 설치하지 않는다.
- 상품 데이터는 `src/data/products.json` 을 쓴다(기획이 바꿀 수 있다).
